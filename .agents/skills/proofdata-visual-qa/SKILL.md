# ProofData Visual QA

## Purpose
Independently review rendered ProofData UI after implementation.

It must inspect:
- visual hierarchy
- first-time comprehension
- ProofData identity
- excessive generic cards
- excessive glass usage
- poor contrast
- typography
- alignment/grid
- spacing rhythm
- responsive behavior
- mobile Compare layout
- focus states
- loading states
- status differentiation
- evidence fingerprint visibility
- consistency between all four verdicts
- fake protocol information
- generic AI aesthetic drift.

## Scoring System
It should explicitly score each route from 1-10 for:
- Identity
- Clarity
- Craft
- Trust
- Responsiveness
- Accessibility
- Hackathon demo impact

Any score below 8 requires recommendations before final visual approval.

It must NOT alter product logic merely to improve appearance.
