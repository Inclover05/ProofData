# ProofData Design Director

## Purpose
This is the highest-authority design skill for ProofData.
Its job is to ensure external design skills improve ProofData without changing what ProofData fundamentally is.

## SOURCE-OF-TRUTH PRIORITY
1. PRODUCT_PRD.md
2. docs/UI_DESIGN.md
3. docs/USER_FLOWS.md
4. docs/PRODUCT_ARCHITECTURE.md
5. validated contract/product semantics
6. proofdata-design-director
7. downloaded third-party design skills
8. generic model preference

External skills must NEVER override higher sources.

## Visual Concept
Define ProofData's visual concept as:
**FORENSIC LIQUID EDITORIAL**

It combines:
- forensic evidence review
- institutional financial/research seriousness
- Swiss/editorial composition
- document/warrant semantics
- futuristic but restrained translucent materials
- evidence fingerprints
- decision boundaries
- GenLayer consensus visibility

The interface must NOT become:
- generic SaaS
- generic DeFi
- neon cyberpunk
- purple AI gradient website
- NFT mint page
- giant rounded-card dashboard
- Apple clone
- Dribbble clone
- Pinterest clone.

## GLASS MATERIAL PRINCIPLES
Glass is a functional material, NOT the entire visual identity.

Use translucent material selectively for:
- navigation surfaces
- evidence inspection overlays
- active process/consensus surfaces
- contextual panels
- overlays and floating analytical information
- selected hero depth.

The Reliance Warrant itself should generally feel more like an authoritative document/dossier than a transparent card.

Glass treatment should aim for:
- subtle backdrop blur
- restrained transparency
- fine hairline edges
- faint internal highlights
- soft depth
- controlled noise/grain
- excellent text contrast
- opaque fallback when transparency hurts readability
- reasonable mobile/GPU performance.

Never sacrifice readability for glass effects.

## DESIGN FORMULA
ProofData =
Forensic information architecture
+ Swiss editorial structure
+ institutional seriousness
+ controlled futuristic materials
+ selective liquid-glass depth
+ clear Reliance Warrant semantics.

Four product routes remain:
- `/`
- `/create`
- `/warrant/[id]`
- `/compare`

Do not add routes just for aesthetics.
