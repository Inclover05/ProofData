# Transaction Lifecycle

## Hash Duality
GenLayer bridges standard browser wallets (MetaMask, Rabby) with its unique consensus mechanism.
- **EVM Submission Hash**: The identifier returned by the browser wallet immediately upon signing. It represents the outer "envelope" submitted to the network RPC.
- **GenLayer Transaction ID / Execution Hash**: The internal identifier of the execution trace generated by GenVM. While currently `genlayer-js` maps them safely for polling, you must distinguish between the EVM payload and the inner GenVM trace when debugging raw RPC data.

## Network Lifecycle States
- **Stored Status**: The current materialized state in the network's consensus data. We strictly track this, avoiding faked countdowns.
- **Decision (Accepted)**: The network's initial quorum has reached a verdict, but it is not yet immutable.
- **Finalization**: The consensus rotation completes, making the transaction irreversible on the network.

## The Success Disconnect
- **Execution Result**: A transaction can be `FINALIZED` successfully by the network protocol but contain an internal `ERROR` in execution (e.g. reverted due to requirements). 
- **Transaction Success**: A transaction is only technically successful if it is `FINALIZED` **and** the execution result is `SUCCESS`.
- **Warrant Application Status**: A transaction successfully completing a `create_warrant` call does NOT mean the warrant is "WARRANTED". The semantic adjudication evaluates the real-world evidence and might return `NOT_WARRANTED` or `CONDITIONAL`. Transaction success simply means the process of asking the question succeeded.
